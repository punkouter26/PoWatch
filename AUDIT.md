## 2. AGENT.md compliance

### Compiler contract — ✅ PASS
Already shown in §1. No inline `#pragma warning disable` was observed in `src/`. `NoWarn` on

### Trunk-based on `master` — ✅ PASS
`git branch --show-current` → `master`. No feature branches in `git branch -a`.

### Domain integrity (no primitive obsession) — ✅ PASS
- `PoWatch.Domain/Models/SubjectId.cs:18-49` — `readonly record struct SubjectId(string Value)` with
  `static SubjectId From(string?)` and `static explicit operator SubjectId(string?)`. Conversion out
  to `string` is implicit (`implicit operator string`) — explicitly justified for "string-context call
  sites" (logging, RowKeys, DTO mapping). `SubjectIdJsonConverter` keeps wire shape as a plain string.
- `PoWatch.Domain/Models/ObservationEventId.cs:13-39` — `readonly record struct
  ObservationEventId(Guid Value)` with explicit `From(Guid)` and explicit `Guid` cast both ways.
  `Parse(string?)` falls back to `None` instead of throwing.

### Vertical-slice non-reference rule — ✅ PASS
`PoWatch.Api/Features/{Archives,Auth,Diagnostics,Fhir,Identity,Observer}` all map endpoints via
`MapGroup(...).RequireAuthorization()`. `ArchitectureBoundaryTests` (`tests/PoWatch.Unit/ArchitectureBoundaryTests.cs`)
enforces 5 invariants by reflection over `GetReferencedAssemblies()` (so unused `using`s cannot
trip it). All 166 unit tests passed.

### No inline colours / tokens from `:root[data-theme]` — ✅ PASS (with note)
Spot-check of `src/PoWatch.Client/**/*.razor` via `grep -E 'style="(background-color|color):'` returns
zero matches. Inline `style="…"` attributes that exist are all `height:` on bar spans driven by
`FormatPercent(...)` from `DailyActivityHeatmap.razor:39-47` and `PatternComparisonPanel.razor:36-37`.
The colour portion comes from CSS classes (`heatmap-bar--urgent`, etc.). Strictly speaking the
AGENT.md rule reads "No inline styles" — those spans violate the letter. The intent ("never
hard-code a colour — every value comes from a CSS custom property") is met. Worth a one-line
decision either way.

### D5 — `[LOW]` Borderline inline-style usage

`style="height:@(...)"` on bar spans in `DailyActivityHeatmap.razor:39-47` and
`PatternComparisonPanel.razor:36-37`. The value is dynamic (computed by `FormatPercent(...)`),
and the colours come from CSS classes / `tokens.css`. Strictly speaking this violates AGENT.md's
"No inline styles". Three options:

1. Leave as is (colour discipline is met; intent of the rule is met).
2. Use `style="--bar-height: …"` + CSS that resolves the custom property (`height: var(--bar-height, 0%)`).
3. Use `data-value="…" attribute + CSS attr() (limited browser support).

Option 2 is the cleanest reconciliation of the rule and the existing pattern.
